# Unit tests

- Run: `cd LarvaSecondsLostExtMod && ant TEST` (compiles `src/` via `COMPILE`, then the tests via `COMPILE_TESTS`, then runs every `*Test` class with `org.junit.runner.JUnitCore`; any failure fails the build). No Scelight runtime needed.
- Sources: `LarvaSecondsLostExtMod/test/hu/aleks/larvasecondslostextmod/` (same package as production, so package-private members are reachable). Class names must end in `Test`.
- Jars: JUnit 4.13.2 + hamcrest-core 1.3 in `LarvaSecondsLostExtMod/test-lib/`. **Never put test jars in `lib/`**: `COMPILE` uses `lib/**/*.jar` and `BUILD_RELEASE` copies it into the release.
- Output: test classes go to `bin-test/` (removed by `CLEAN`). Tests compile with `source/target 1.7`, so lambdas etc. are rejected, like in production code. The build uses whatever JDK `ant` finds (JDK 17 here, with `-source 7`); Java 8+ API calls are not caught by the compiler, avoid them manually.
- `BUILD_RELEASE` does not depend on `TEST`. Release routine: `ant TEST BUILD_RELEASE`. The release jar, release folder and deployment zip contain no test classes or JUnit/hamcrest jars (check with `unzip -l`).
- Tests use synthetic data only. Anything that parses replays is a golden/integration/manual check.
- Integration golden (not part of `TEST`, needs the installed Scelight and Java 8): `ant TEST_GOLDEN_MULTI` runs `LarvaMultiAnalysisCli --multi ../benchmark-data/queensMoved` with `/usr/lib/jvm/java-8-openjdk-amd64/bin/java` (override with `-Dgolden.java=...`), writes `bin-test/epic17-multi-queensMoved.actual.txt` and fails if it differs from `test/golden/epic17-multi-queensMoved.txt`. `ant GOLDEN_MULTI_REGENERATE` overwrites the golden (review the diff, commit by hand). The dump has file names only, UTC dates, fixed number formats, so it is the same on every machine; the CLI keeps Scelight's bootstrap chatter off stdout.
- Run the dump by hand: `java -cp "bin:<sdk jar>:lib/*:<Scelight .sldat files>" hu.aleks.larvasecondslostextmod.LarvaMultiAnalysisCli --multi <dir> [--all-modes] [--no-prefilter] [--scelight-app-dir <Scelight>]` (classpath as in `knowhow/epic17-batch-spike/env.sh.txt`). Do not run it while Scelight is running (single-instance socket).
- **View-model golden (E17-S15):** `ant TEST_GOLDEN_MULTI` also runs `LarvaMultiAnalysisCli --multi ../benchmark-data/queensMoved --view-model` (the multi page's display model as text, fixed locale and UTC) and then `LarvaMultiViewGoldenCheck <golden> <view dump>` (a `main` class in `test/`, compiled by `COMPILE_TESTS`, no `Test` suffix so JUnit skips it), which compares every cell string with the formatted values of `test/golden/epic17-multi-queensMoved.txt` (per bucket and phase: phase end `m:ss` with `k/n` (S17: `end=` in the dump, was `length=`), uptime, rates, rankings; milestones with `k/n`). `LarvaMultiViewGoldenCheckTest` covers the comparison on synthetic data inside `ant TEST`. `ant TEST_GOLDEN_MULTI` now depends on `COMPILE_TESTS` (which wipes `bin-test/`), then writes `bin-test/epic17-multi-queensMoved.actual.txt` and `.view.txt`.
